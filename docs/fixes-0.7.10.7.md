# Fix lists — 0.7.10.7 (the top of the screen, again)

Follow CLAUDE.md. One branch, **Opus** (it needs careful testing of iPhone-only behaviour). Bumps VERSION to 0.7.10.7 and CACHE to match (only branch of this round).

Petros still sees the blur under the clock / Wi-Fi / battery and a soft title on pages and in windows (screenshots in the chat: Active Exercise, Workout Done, Food Library, My Food Log). A solid strip now exists (`body::before` in theme.css, height `env(safe-area-inset-top)`), but it did not fix it. Findings and a plan, in order:

## shell (Opus)
1. **The strip sits behind every window.** `body::before` has `z-index: 8`, but windows (`.overlay`, `z-index: 10` and the `zTop` values set by ui.js) are drawn above it, so inside a window (Active Exercise, Workout Done, Add Exercise, Settings pages, Form page, chats) the strip is not there at all and scrolling content shows under the clock. Make the strip a real top layer: a fixed element above every window and sheet (above the highest `zTop` value), below only toasts that must stay readable, `pointer-events: none`, solid `var(--t-bg)` (the page or window colour, so it does not look like a black bar on a light theme), height exactly the status-bar area. Check it in Dark and Light and on every window type. A desktop browser has no status bar, so test with the safe area faked at 59 px (a test stylesheet that replaces `env(safe-area-inset-top)`), scroll a page and an open window, and make sure **nothing but the strip colour is visible in the top 59 px**.
2. **Move titles and windows lower (Petros's idea).** Add one theme variable `--topgap` (start with 12 px) and add it **below the status bar** for: page headers and titles (`--hpad`, `section.page>header`, layout.css), full-screen windows (`--topP`, theme.css), the Active Exercise / Workout Done / Add Exercise / Settings / Form / Targets / Theme windows, and the floating chat windows, so no title or back arrow ever sits right against the status bar. Titles keep the same size and style. Check every page and window at 390 px: nothing is cut, no content jumps between tabs, the back arrow and title stay on one line, headers are all the same height, and lists and cards start in the same relative place.
3. **Sharp titles.** Make sure no page or window title sits in a layer that iPhone draws softly (any `transform`, `opacity`, `will-change`, `filter` or `backdrop-filter` on the title or its ancestors once it has settled; a title inside a sticky element that has `isolation: isolate` and a transition). Fix what you find; list it in the pull request.
4. **iOS may be blurring the top edge by itself.** On the newest iPhone software, a Home Screen web app that runs under a see-through status bar (`apple-mobile-web-app-status-bar-style` = `black-translucent`, index.html) may get a soft blur at the top edge from the system. We cannot see that in a desktop browser. So prepare an **easy experiment** that Petros can run on his phone, without a second build:
   - Keep the current setting as the default.
   - Add a **Settings › Appearance › Status Bar** choice: **Transparent** (today) and **Solid**. Solid sets the status bar style to the solid kind (`black`), so the page starts below the clock and nothing can ever show under it. Because iPhone reads this setting only when the app is opened, the text under it says: "Takes effect the next time you open the app. If nothing changes, remove the icon and add it again." Save the choice with the other settings, and write the meta tag from the saved choice as early as possible at start-up (before first paint) in index.html's head script.
   - In Solid mode the safe-area values become 0, so everything must still look right: check with the faked safe area set to 0 that no screen loses its top spacing (`--topgap` still applies).
   - In Light theme, Solid shows a black bar above a light page; make sure that looks acceptable, or say in the pull request what Petros should pick.
   - Explain in the pull request, in plain words, how Petros tests it on his phone.
5. Check with screenshots (fake safe area 59 px, 390 px wide, Dark and Light): a page at the top and scrolled, an open window scrolled, Active Exercise, Workout Done, the Add Exercise picker, a chat window.
