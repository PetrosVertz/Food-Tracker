# Decisions (only the hard-to-reverse ones)

**D1 · No build step, no framework, no IndexedDB (2026-11-22).** Classic scripts + localStorage stay. Evidence: a 2-year power-user profile is 1.2 MB (localStorage limit ~5 MB); saves take <10 ms; start-up ~375 ms. A bundler/ESM move would touch all 47 scripts for no measured gain today. Revisit when data nears ~3 MB or a native build needs modules.

**D2 · Import is planned on copies and saved all-or-nothing (2026-11-22).** `Backup.plan` (pure) + `Store.saveMany` (journal + roll-back). Rejected: a full staged "import preview" screen — more UI/strings than the risk needs, since import only adds/fills and never deletes. A preview can be added on top of `Backup.plan` (it already returns counts and `changed`).

**D3 · Live workout in backups (2026-11-22).** Exported as `gym.active`. Restored only if this phone has no live workout and it was not finished since; then the existing "left open" rule (`checkAbandoned`) decides. A live workout on the phone is never replaced. *Petros may prefer "never restore a live workout" — one line in `Backup.plan`.*

**D4 · Service worker takes over at once, never reloads a page (2026-11-22).** Kept `skipWaiting` + `clients.claim` (network-first, no `controllerchange` reload), so a workout in progress is not interrupted; the new version runs at the next start. Caching limited to `SHELL` files with 200 answers.

**D5 · Two tabs: not solved yet — decision needed.** Two open copies of the app can overwrite each other's newest changes (localStorage has no compare-and-swap). Options: (a) warn and offer reload when another tab saves (`storage` event; small, needs 1 string), (b) single-tab lock, (c) leave as is (a phone PWA is usually one window). Recommendation: (a).

**D6 · AI deadline values (2026-11-22).** 60 s for normal requests, 120 s for receipts / web look-ups, each try limited to the time left. Before: up to ~5–7 minutes. Change in `deadlineFor` (ai-provider.js) if real use shows receipts need longer.

**D7 · Athlete OS events come from Store, not from feature files (2026-11-22).** `Store.save` already diffs every synced record for the sync table; `Store.onChange` hands that diff to `AthleteEvents`, which maps Store names to event types. So gym.js / today.js emit nothing and cannot forget to. Rejected: `emit()` calls in every save path (≈40 call sites across four branches' files, easy to miss one). Cost: the event says *what record* changed, not *why* (a deleted diary entry and a moved one look alike); enough for cache invalidation and context.

**D8 · Coach memory is the user's own words only, on this phone (2026-11-22).** Notes come from fixed sentence rules over the user's typed chat message (EN + GR), never from an AI answer, so an AI guess cannot become a "fact". Device-only (`athleteMem`, like `aiKnow`); not in backups or sync; Settings › AI › Copy as Text exports it. *Petros may want it in backups (then it needs an import rule and store-test cases) and may want a confirm card before a note is kept (today: kept at once, with Undo in the toast).*

**D9 · Context goes through the existing `AI.knows()` door (2026-11-22).** Every prompt that already called `AI.knows(topic)` gets the Athlete OS block with no prompt rewrite; coach personalities and JSON shapes are untouched. The block replaces the old daily-summary text (which is still inside it, as its lowest-priority part) and has a hard letter budget per specialist (900–1500 letters ≈ 225–375 tokens; the old block could reach ~1700).

**D10 · One coach personality, as plain text in the same prompt (2026-11-22).** `js/athlete/persona.js` holds the voice, humour, length and honesty-about-data rules for Food Coach, Gym Coach and Fridge AI; each specialist keeps only its expertise and answer shape. Settings are device-wide (`settings.coach`), so every coach follows them. Rejected: a second "style" AI pass (doubles cost and time) and per-coach personality settings (the spec wants one coach). Feature usage is a state slice (`usage`) read from the existing records, not a new tracker: it says how complete the records are, never what the user did. *Petros may want: the personality in backups (today device only, like the API key); the persona on the non-chat tools too (Fill My Macros, meal plans); a Greek-specific tone note.*

**D11 · Weekly streak is a replay, not a ledger (2026-11-22, Change #13).** `js/streak.js` saves only what cannot be worked out again (start date, the old streak carried over, the planner-change log, the target locked for each week, the personal best) and replays weeks, saver grants, uses and the Consistency Challenge from `sessions`. So a restart, a restore or weeks offline give the same answer and a saver can never be granted twice. Reconciliation policy: editing, deleting or importing a past workout re-judges its week (a deleted workout can undo a success, an imported one can rescue a week); the personal best never goes down. Extra rules on top of the spec: a saver is not spent when the streak is 0 (nothing to protect); a week pair that earned a bonus cannot start the next pair; the old daily streak's workout days before the first week carry over once (`base`), and the old Longest Streak stat seeds the personal best. Warnings are in-app (one toast per message, `ui.stk`), since the app has no notification system. *Petros may want: past weeks frozen instead of re-judged; the Stats shuffle button removed (today it starts a new 24 h set by hand); a native notification once the Capacitor app exists.*

**D12 · RECOVERY+ anatomy is traced from the approved sheets (2026-11-22).** Every dark area between the artwork's white lines became its own path (tools/recovery-anatomy/), so silhouettes and line positions are the approved drawing's; shading is the artwork's own light areas as faint white overlays. Where the artwork draws one shape for two heads (lats + lower back, pec mid + lower, female front + side delt, female back of neck), the second head is a piece drawn on top only when its colour differs, so the neutral figure shows no seam. Exercise picker / info keep `gym-anatomy.js` (pixel-identical to main).

**D13 · RECOVERY+ food judgments need "finished" days — decision needed.** The spec forbids treating partial logs as under-eating, and the app has no "I've finished logging today" mark. So calorie-vs-target and protein-gap insights (incl. Bulk / Cut goal checks) stay "unknown" in real use; the engine already reads `days[d].foodDone` and is tested with it. Options: (a) add a small optional "Finished Logging Today" control on Today (log branch, a new `days` field, store-test case); (b) leave it unknown. Recommended: (a).

**D14 · Sleep has no source yet.** `evaluateSleepSupport()` is built and tested, but the app has no watch / Health link, so sleep shows "No sleep data is connected". A future Health adapter only needs to provide a global `athleteSleepRecords` function.

**D15 · Kitchen became Food Library sections (2026-11-23, Petros).** Fridge (renamed Inventory) and Groceries are pills 4 and 5 of the Food Library carousel and two hub tiles; the bottom bar has four tabs (Today, Gym, Food Library, Profile). Hashes `#fridge` / `#groc` and all saved data (`fridge`, `groc`, `ui.noKitchen`) are unchanged, so old links and backups still work. The Settings switch keeps its job (off = the app and the AI see an empty fridge) but no longer removes a tab: the two pills and tiles stay, greyed out.

**D16 · Exercise Settings can be per exercise (2026-11-23, Petros).** The first gear tap asks: same for all, or individual. Individual stores only what an exercise changed (`settings.gxEx[exId]`), so everything else follows the general settings and switching back loses nothing. Ranking, Leaderboards, Tips and Sounds are always shared (one place, `GX_EACH` lists the per-exercise ones).

## Cardio left the app (24 Nov)
Petros: no cardio exercises (jumping jacks, treadmill, bike …) in the picker or presets; a Cardio tab may come later, maybe. The 22 built-in cardio exercises were removed from `LIB_RAW` (their ids are kept in `CARDIO_GONE`, js/data/gym.js). Old workouts keep their history (unknown ids read as plain exercises); saved presets lose cardio exercises, a preset that was only cardio is removed and leaves the week plan (js/wire/05-nav-cook-gym.js). The old cardio card code (`cardioRow`, `isCardio` guards) is inert and can be deleted when a future Cardio tab is designed.

## Timed holds have their own rank and factor (24 Nov)
Holds keep SECONDS in the set's reps field (no saved-data change). `HOLD` gives each its seconds-per-rep-equivalent for volume and RECOVERY+. Their rank is separate: seconds needed per level, body weight and an optional belt (`holdBw` in js/data/rank-v04.js, PROVISIONAL values written for the app; replace when real data exists). Open: whether the hold factors (8 s for a dead hang, 10 s for a plank …) feel right in RECOVERY+ after a few real weeks of use.
