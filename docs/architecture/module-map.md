# Module map — where each feature lives

Source-verified 2026-11-22 (v0.7.10.7 + V3 hardening). **The code wins over this page**: if a path or symbol here is wrong, grep, fix the code task, then fix this row. `node tools/check.js` fails when a path or `name()` below stops existing.

All scripts are classic browser scripts sharing one global scope, loaded in the order of `index.html`:
config → platform (`store`, `backup`, `phone`, `ai-provider`, `ai-usage`, `ai`) → data (`strings`, foods, gym, anatomy, rank bench) → helpers (`core`, `draft`, `ui`, `coach`) → features (`gym-intel` right after `gym`) → `know` → Athlete OS (`js/athlete/*`) → `wire/01…10` (state, listeners, first render). A file may only use, **at load time**, what earlier files define; inside functions anything global is fine. (The unloaded `wire/11-v059.js` was deleted in the activation round.)

## Worked routes (dry runs, V3 §4F) — what to open for three typical future tasks

**1. Exercise Picker refinement (V27: Upper | All Muscles | Lower, progressive pill filters, creator).** Open `js/expick.js` › `openExPick()`, `pkList()`, `pkDrawFilters()`, `pkDrawResults()`; creator `js/excreate.js`; muscle list `EXM` and custom records in `js/excustom.js`; search stays `js/exsearch.js` › `ExSearch.query` (do not fork it); muscle/head/equipment data `js/data/gym.js` (`LIB_RAW`, `HEADS`, `EQ`); usage order from `sessions` (read only, completed sets). Picker + creator CSS: the V27 block in `css/workout.css`. Contract: exercise ids are frozen; `exCustom` only gains optional fields (old fields unchanged, read by older code and GB1 codes). Picker cards and exercise info draw the RECOVERY+ figure only through `raExerciseSVG()` (pure drawing, no recovery numbers); never read RecoveryPlus in the picker. The creator keeps the tappable `anatomySVG()` map. Gates: `check.js` exercise library + `tools/exsearch-test.js` + `tools/expick-test.js` + boot; manual: phone screenshot of the picker in both themes and languages.

**2. Food Coach answer quality.** Open `js/today.js` › `logQPrompt()`, `logQSend()`, `logQReply()`; meals `js/meal.js`; facts via `AI.knows` (`js/know.js`); the request goes through `gemini()` (= `AI.ask`) → `AIProvider.run()` (deadline, retries, usage) — never `fetch` directly. Safety: the coach only proposes; diary writes happen in the card's log action with undo (`dayLog` + `saveLog()`), so a prompt/provider change cannot write food logs by itself. Gates: `tools/meal-test.js`, AI provider checks; manual: a few real chats.

**3. RECOVERY+ consumer.** Read `RecoveryPlus.snapshot()` (js/recovery-plus.js; contracts.md › RECOVERY+), never re-compute; Gym Coach does through `GymIntel.recovery()`, Athlete OS through `AthleteState` recovery. "unknown" stays unknown (never "ready"). How it works: docs/architecture/recovery-plus.md. Gates: new pure tests next to the engine (like `tools/store-test.js`), boot, manual anatomy check.
